Welcome to machkernel.org

Yes, this is the other kind of kernel. No popcorn here, though you are welcome to bring some.

Hello, and thank you for stopping by. This is a short, independent reference on the Mach kernel. You may have met the name in macOS, in the GNU Hurd or in an operating systems course. Whatever brought you here, we are glad you came, and you do not need to know anything about kernels to start.

We keep things small. Even a microkernel knows when to stop.

What Mach is

Mach is an operating system kernel that began at Carnegie Mellon University in 1985. It rests on a simple claim: a kernel needs only a few things. It needs a way to run code (tasks and threads), a way to manage memory, and a way for programs to send each other messages. Everything else, such as file systems and device drivers, can run as ordinary programs outside the kernel. The kernel stays small, and the rest of the system gets on with its own business.

The CMU project ended in 1994, but the kernel kept going. Mach is the base of XNU, the kernel inside Apple's macOS and iOS, and it is the default microkernel of the GNU Hurd. Its virtual memory design was adopted into 4.4BSD and is still in FreeBSD.

Where to start

I am new to kernels
Read Concepts first. It covers tasks, threads, ports, messages and virtual memory in plain terms. If a word is unfamiliar, the Glossary has a short definition.
I want to know how Mach got here
History runs from Rochester in the 1970s to the devices that run Mach today.
I have a specific question
Common questions answers things like whether Mach is slow, whether it is still used, and how it compares with L4. We answer the speed one honestly, and we promise not to panic.
I want to know which systems use it
Implementations lists the kernels descended from Mach and which ones are still alive.
I want to read the code
Reading the source says where to find it and which directories to open first. Reading lists the original papers, the CMU archive and some later criticism.

About this site

The site is small on purpose and does not try to be complete. It is not run by Carnegie Mellon University, Apple or the GNU project. It is written and maintained by the people building KyberOS, a pure Mach microkernel OS.
